## 贡献没有被证明的原因

| 观察 | 当前证据 | 合理解释与限制 |
|---|---|---|
| 去掉产品仅下降 0.00722 MRR | 完整−去产品区间 [-0.0122, 0.0278] | 不能认定产品关系稳定有效 |
| 去掉 CWE 仅下降 0.00417 MRR | 完整−去 CWE 区间 [-0.0194, 0.0271] | 不能认定 CWE 关系稳定有效 |
| 去掉战术/阶段下降 0.00972 MRR | 区间 [-0.0014, 0.0236] | 不能把确定性映射链单独解释为经验证的推理贡献 |
| CWE Frequency 更差 | 6 条真实目标因条件计数为零而落到约第 348.5～350 名 | 稀疏条件频率的零分大并列，需要平滑；不等于 CWE 知识没有价值 |
| 训练继续后目标损失很低，背景损失仍接近 0.69 | 主要 R-GCN 最后目标损失约 0.017～0.031，背景关系大多约 0.63～0.72 | 与先学会热门技术/背景重构不足的解释一致；仅凭损失不能断言单一因果 |

所有 51 次训练都因 patience 停止，运行 35～157 epoch，没有达到 500 epoch 上限。主 R-GCN 的 best epoch 为 5、13、16、20、22。单纯取消轮数上限不能解决已观察到的排名退化；继续训练已出现 Dev 停滞或下降。

均匀负采样的竞争强度值得优先验证：对一条具有单一已知正例的 Train 目标，在 697 个候选中合法替换尾实体有 696 种；另外 5 种已见目标技术被抽到的单次概率仅 5/696≈0.72%，10 个负样本中至少一次遇到它们的概率约 6.96%。这是根据采样规则计算的期望，未声称逐 epoch 日志实测。模型可能只需要把少数有正例的技术与大量无目标正例技术分开，就能降低目标损失，未充分学习常见技术之间的区分。

另一项开发选择风险是只用一个种子调参。原选择中 DistMult 与 R-GCN 都选 64 维、学习率 0.003、dropout 0.3；DistMult 的开发调参赢家 MRR 0.7403，换五个种子后的 best-Dev 均值为 0.6791。R-GCN 对应 0.7083 与 0.6806。它们是在同一 Dev 上的选择/稳定性诊断，不是最终泛化结论；提示下一版应使用跨划分和多个开发种子。

## 数据语义与来源核验

官方 ATT&CK 显式记录准入不等于独立人工语义审定。当前继承目标陈述 37 条、官方准入陈述 226 条、官方唯一关联 146 条、pending 68 条；NVD 158/158 成功。187 个引用中 146 个可读取文本、21 个只保存二进制未语义检查、20 个不可用；可读取不表示对每条技术映射完成语义核验。

有实际需要复核的类别边界。例如，固定 ATT&CK 记录将 ZxShell 使用 CVE-2011-2462、CVE-2013-3163、CVE-2014-0322 的行为挂到 T1190；原 Talos 报告讨论的是钓鱼投递和这些漏洞的利用，归档 NVD 将后两项描述为 Internet Explorer 漏洞。T1190 的定义强调公开可访问应用的利用，T1203 强调客户端应用的利用。**这是来源映射与技术定义可能不一致的审计线索，不是已经裁决的标签错误**，也不允许据此追改 v1 分数。

CVE-2024-30088 同时具有 T1068 与 T1203 官方标签；现有 NVD 描述为 Windows 内核提权。需要依据具体攻击语境核验多标签，而不是把任何代码执行都自动视作客户端利用。来源确认层、语义审定层、规则推导层与预测层必须分开记录。

这些例子也说明，仅凭产品和 CWE 未必能唯一决定攻击技术；技术通常还取决于公开暴露、客户端交互、已有权限等攻击条件。未提供场景条件时，本章宜表达为“可能关联候选排序”，并允许多个合理标签。

### P0：结果诊断与证据保留——本次已完成

### P1：新版本数据核验与评价登记

1. 对全部 165 条既有目标关联按原始来源、技术定义和具体攻击语境做审计；多标签、跨类别和直接利用/利用后活动列为优先项。任何新裁决保存到独立 v2 路径，记录旧/新值、证据、理由和裁决者；v1 不追改。
2. 从新的厂商/研究机构原始威胁报告扩充具有明确利用证据的 CVE—技术关系，NVD 只补充产品/CWE背景。不能从“存在漏洞”“在 KEV 中”“CWE 看起来类似”直接推导实际技术关联为 Gold。建议审查规模上限 600 个候选 CVE、300 篇原始报告；不足时停止并报告，不降低证据门槛凑数量。具体 HTTP 请求/重试上限在新登记中确定。
3. 推荐总样本目标 300～500 个合格 CVE，新增最终 Test 60～100 个从未用于当前错误分析/选优的 CVE。该规模是实际工作目标，不是功效保证。主要技术建议每类至少 15 个 Test CVE；无法覆盖时单列类别限制，不补造标签或根据效果选样。
4. v1 的已分析 Test 可用于 v2 开发，但不再承担 v2 最终检验角色。新 Test 排除仓库既有暴露和整个 v1 目标样本；C4 旧 Test Gold 仍不打开。按 CVE 分组，明确去重和同源报告关系；具备足够来源组时另做报告分组压力验证。
5. 保留 697 全候选域的主评价口径。若要另设符合利用范围的候选子域，必须在新评分前登记并作为单独评价，不能为追求高分事后缩小候选。
6. 新注册主指标仍为 filtered macro-CVE MRR；同时预设技术宏平均、逐技术 Hits@1、稀有类样本数、背景共享/不共享分组和完整 seed 分布。稀有类只有一个样本时只作案例报告。
7. 开展真实双人独立标注时，保存裁决前记录再计算 IAA。AI 检查或最终 Gold 的一致性不能替代它；未具备该证据时继续准确标注来源确认的范围，不宣称已有独立人类 IAA。

停止条件：语义歧义未裁决、独立最终样本不足、有效开发划分不足或请求预算耗尽时，停在开发证据与材料准备状态；按路线 A 完整交付当前结果。不得自动替换协议或反复开启新的最终 Test。

### P2：受控开发实验——优先检验区分能力

固定现有 64 维、学习率 0.003、dropout 0.3 作为起始参数，先不扩大参数网格。对开发数据预先固定 3 组 CVE 分组折、3 个开发种子，比较四个学习实验臂：DistMult+原均匀负采样、DistMult+混合负采样、R-GCN+原均匀负采样、R-GCN+混合负采样，共 **4×3×3=36 次**训练。新登记中固定全部折、种子和输入绑定。

混合方案：目标关系的 10 个对比样本中，5 个从全部合法候选中抽取，5 个从仅依据该折 Train 正例得到的其他已见目标技术中抽取；仍排除所有已知正例，目标头实体仅来自该折 Train。合法已见候选为空（包括所有已见候选都是该 CVE 已知正例）时退回全域并记日志；全域也无合法候选时明确失败，不能生成正例碰撞或无限重试。辅助关系采样和损失权重保持原值。未观察到的关系只是训练对比样本，不能被升级为已核验事实负例。这一实验控制了采样策略，使变化可归因。

同折比较四个简单基线：全局 Frequency、原 CWE Frequency、带全局先验平滑的 CWE Frequency、基于产品/CWE 的 Train 邻居投票。平滑基线可采用 `score(t|w)=(count(w,t)+alpha×p_train(t))/(count(w)+alpha)`，缺失/无支持 CWE 退回全局；alpha 候选仅 1、5、10，并按三折 Dev 规则选一个。产品/CWE 近邻采用两类集合 Jaccard 相似度各 0.5、按相似度加权 Train 目标票数，无近邻退回全局，不使用 held-out 目标。它们帮助判断复杂模型是否超过可解释的背景关联方法。

推荐进入确认实验的开发门槛：预先固定的最佳简单基线对照下，混合 R-GCN 的三折三种子合并 macro-CVE MRR 提升至少 0.02；9 个折/种子组合中至少 6 个改善；主要技术宏平均下降不超过 0.01。记录原始 Top3 是否因 CVE 而变化，但不能把排序多样性本身当作效果提升。门槛只决定是否值得继续，并不构成独立泛化或统计显著性证明。

没有达到门槛时停止该模型升级，归档为开发负结果。不得看新 Test 寻找参数，不筛掉不利种子，不自动进入下一轮网格。若图模型与简单背景基线相近，章节可突出图谱构建、来源追溯与候选生成，并如实降低模型创新结论。

### P3：冻结后一次性确认

仅在 P1/P2 完成后，新登记四个学习主臂各 5 个最终种子，以及混合 R-GCN 的三组消融各 5 个种子，共 **35 次**训练。它们使用同一新图、同一目标划分和完整候选域；消融沿用主模型参数，删除对应背景边及辅助损失，目标损失不改。全部运行完成后才统一输出新 Test 评价。

将混合 R-GCN 相对开发阶段选定的最强简单基线登记为主要比较；R-GCN/DistMult、原/混合负采样及各消融作为预设解释性比较。平均五种子后做 CVE 配对区间；来源组足够时增加按来源组重采样的敏感性报告。报告效果量、区间与类覆盖，不能把多个随机种子当作独立数据集重复。Test 不能触发选优、补数据或新的确认轮次。

若新 Test 仍无稳定提升，论文报告负结果；可以保留模型作为候选生成原型，但不能将“知识融合改善预测”写为已证实结论。

### P4：第四章输入质量实验，按覆盖条件开展

仅有当前 21 篇旧 Dev 不足以支撑完整流程结论。先建立覆盖新 Holdout 的原始文本抽取输入及来源绑定，严格保证文本抽取模型/提示词未见相应 Gold；事实核验与模型选择使用独立角色。第四章/第五章 Test、formal 和 IAA 要求分别登记，不混用旧门禁。

若只有有限预测覆盖，继续只报告覆盖范围内的扰动分析。若覆盖条件具备，可复用已选混合策略运行 DistMult/R-GCN 各 5 种子，最多 **10 次**训练，不另调参。任何需要新增 LLM 抽取的任务必须单独登记 API 调用/费用预算，当前授权的分析没有调用外部模型。

### 后续候选，仅在开发证据支持时登记

背景关系共享不足或近邻方法无法区分时，可考虑产品类型/CWE层级等目标独立特征，或仅基于 NVD 描述的 TF-IDF 输入。NVD 描述与技术定义文本可提供语义特征，但不能输入含 CVE—目标技术答案的 ATT&CK procedure、旧抽取答案、Test 标签或从目标边计算的特征。新编码器/文本特征每次只改变一个因素。当前不推荐同时加入注意力、更多层、多个解码器或大模型。
