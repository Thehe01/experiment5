## 2. 预测集中发生在哪里

以下为各方法九个 mixed 检查点的均值。

| 诊断量 | DistMult mixed | R-GCN mixed |
|---|---:|---:|
| 每折 155 个查询的 raw Top3 技术并集 | 4.33 | 3.78 |
| Top3 恰为 T1059/T1190/T1203 的查询比例 | 79.00% | 90.97% |
| 单个查询分数排序与跨查询平均排序的 Spearman | 0.9679 | 0.9943 |
| 平均分数与 Train 频数 Spearman，174 个已监督技术 | 0.8830 | 0.8431 |
| 平均分数与 Train 频数 Spearman，全部 697 候选 | 0.6864 | 0.7474 |
| 按查询标准化后，共同技术分数形状的方差占比 | 99.17% | 97.80% |
| 按查询标准化后，查询×技术交互的方差占比 | 0.83% | 2.20% |

标准化是在每个查询的 697 个分数上减均值、除标准差，再作两因素正交方差分解。97.80% 指跨查询共同的技术分数形状，不等于“频率解释了 97.80%”，也不是原始分数方差。R-GCN 原始分数的查询主效应、技术主效应、交互项分别为 50.05%、42.78%、7.18%。背景可能大幅改变分数尺度，同时保留大部分技术顺序。

全部 697 候选中有 523 个无 Train 目标支持，频数大量并列，所以同时报告已监督 174 类的相关性。较强相关支持频率偏置这一解释，但相关不能证明完整成因。没有消息传递的 DistMult 同样高度集中，说明不能仅将问题归因于 R-GCN 层数。

R-GCN 的漏洞表示还有差异：

| 表示层 | 平均两两余弦 | 去均值后能量占比 | 去均值后有效秩 |
|---|---:|---:|---:|
| 输入层 | 0.8843 | 12.27% | 30.92 |
| 第一层 | 0.7624 | 24.69% | 14.01 |
| 第二层 | 0.7705 | 25.07% | 10.95 |

九个检查点的第二层余弦均低于输入层。表示维度有所压缩，但不存在“层数增加后所有漏洞比输入更加趋同”的现有证据。区分最终未充分体现于候选排名，比单独宣称实体表示彻底塌缩更符合数据。

已监督技术的向量范数与 Train 频数相关为 −0.7464，方向也不支持“热门技术只是范数更大”。这不排除方向、关系权重及共同查询分量形成先验。

## 3. 模型是否使用背景

固定全部模型参数，将当前折 Dev CVE 的背景整组换给另一 Dev CVE。采用三个提前固定的种子和无固定点置换；联合置换保留同一漏洞的 CPE/CWE 配对以及全局背景尾节点度数。另做 CPE 单独置换、CWE 单独置换与删除 Dev 两类背景的对照。节点、技术候选、Train 目标和 Dev 标签不变。

| 固定参数对照 | 对照后 MRR | 相对原 MRR | Top3 集合改变比例 |
|---|---:|---:|---:|
| R-GCN：联合置换 CPE/CWE | 0.301043 | −0.018356 | 10.73% |
| R-GCN：只置换 CPE | 0.317184 | −0.002215 | 4.01% |
| R-GCN：只置换 CWE | 0.305369 | −0.014030 | 9.25% |
| R-GCN：删除 Dev CPE/CWE | 0.302796 | −0.016604 | 20.29% |
| DistMult：联合置换，负对照 | 0.310902 | 0 | 0% |
| 邻居投票：联合置换 | 0.193966 | −0.182831 | 94.98% |

联合置换后 R-GCN 分数相对 L2 变化为 34.82%，但原分数与新分数的查询内排序 Spearman 仍为 0.9922。它会响应背景，响应更多表现为分值变化，候选先后顺序通常较稳定。

R-GCN 联合置换的三折平均 MRR 变化分别为 −0.01605、−0.01543、−0.02359；邻居投票为 −0.15654、−0.18210、−0.20986。不能只凭整体均值忽略检查点差异：例如 f1/seed20261021 的 Top3 改变约 60.43%，而多个检查点为 0%；有两个检查点联合置换的平均 MRR 微升。逐单位和逐查询证据均保留。

当前 CWE 的置换影响比 CPE 更大；单关系对照只使用第一个固定种子，不能据此宣布 CPE 无用。训练已学到的共享背景嵌入、CVE ID 通道及其自环仍存在，置换没有重训。结果检验的是这些已选模型的敏感度，不等于训练时背景贡献的因果估计。

## 4. 为什么不能直接去偏或只扩样本

在现有检查点上做两个解释性分数探针：

| R-GCN 探针 | MRR | raw Top3 技术并集均值 |
|---|---:|---:|
| 原模型 | 0.319400 | 3.78 |
| 减去每类跨 Dev 查询的平均分数 | 0.126861 | 34.00 |
| 将技术向量归一化后评分 | 0.299333 | 5.89 |

更多样的预测不自动意味着更准确。完整去掉共同分数会一起丢掉有用的热门技术先验，而剩余查询差异不足以支撑排名。这是诊断探针，跨 Dev 计算的列均值不是可直接推广的正式校准方案，也没有重新选择超参数或检查点。

更多长尾正例仍可能有帮助，但本轮没有做样本规模学习曲线，不能量化扩样收益。现有 880 CVE 开发池里，邻居投票已能从同一背景取得明显更好的排名，因此“样本少”不足以单独解释差距。数据覆盖、目标边等权训练与 CVE 等权评估的差别、辅助目标和查询表示设计仍是待验证的机制假设。

## 5. 下一阶段只保留一个候选

建议预注册一个 **DistMult context-pool / mixed 对照**：保留原技术向量、关系评分、损失、混合负采样与停止口径；唯一主要干预是把 CVE 自由 ID 查询向量换成直接由其 CPE/CWE 背景构造的查询向量。两类背景分别均值池化，两类均存在时等权平均，只有一类时使用该类；共享背景向量可学习，不加入文本或新标签，不使用 Dev 目标来生成表示。

这检验一个具体假设：新漏洞的目标监督不能直接更新其 CVE ID 通道，直接让目标损失作用到共享背景查询，是否能形成更强的条件区分。它不预先断言 ID 记忆或辅助损失已被证明为根因。与原 DistMult mixed 的配对比较最能检验该查询构造变化；原 R-GCN mixed 和邻居投票同时保留为成绩参照。

候选开发预算应另行登记为 3 折×原 3 种子=9 个新训练单位，原 36 单位不重训。固定其余超参数，不开第二候选或搜索。主要验收继续看与邻居投票的 MRR、0.02 平均增益、至少 6/9 胜出及主要技术宏 MRR 差不低于 −0.01；背景置换敏感度和 Top3 多样性只作机制诊断，不替代原进阶指标。改进若不满足门槛，就保留负结果并停止。

**这一项目前只有候选方案，没有训练登记或启动。本次用户“开始”所授权的前两步已经完成。155 保留组与确认实验继续保持未启动状态。**
